Parte 1

CSP: problemas de satisfacción de restricciones

Un CSP describe un problema con tres piezas. Luego un algoritmo general (el mismo para un sudoku, un horario o un mapa) busca valores que cumplan todo. Tú solo describes el problema; no programas la solución a mano.

En K'iti Yachay, cada ronda muestra el elemento correcto y tres distractores. Hoy Banco.distractores() los elige al azar. Con un CSP se eligen al azar pero respetando reglas pedagógicas.

Variables
Lo que hay que decidir.D1, D2 y D3: los tres distractores de la ronda.
Dominios
Los valores posibles de cada variable.Los 10 animales del banco de escenarios.
Restricciones
Las reglas que la solución debe cumplir.No puede ser la respuesta, no debe confundir, y cada distractor de un ambiente distinto.

Las restricciones de este ejemplo

  • Unaria (una sola variable): ningún distractor puede ser la respuesta del paisaje.
  • Unaria: nada que pueda vivir de verdad en ese paisaje. En la granja también hay patos y palomas; si aparecen, el niño “se equivoca” con razón.
  • Binaria (dos variables): D1 ≠ D2 ≠ D3, y cada uno de un ambiente distinto (agua, frío, calor, campo y ciudad), para que las opciones se distingan bien.
  • Opcional: la educadora pide “nada del frío”. Con eso, en la granja no hay solución; mira cómo lo descubre el backtracking.

Qué hace cada etapa

  1. Consistencia de nodo. Aplica las restricciones unarias y borra de cada dominio los valores que nunca podrían servir. Es barato y se hace una sola vez.
  2. AC-3 (consistencia de arco). Para cada par (Di, Dj) borra los valores de Di que no tienen ningún compañero válido en Dj. Aquí casi nunca borra nada, y eso enseña algo: AC-3 solo mira pares, así que no ve que con “nada del frío” faltan ambientes para tres distractores.
  3. Backtracking. Asigna una variable a la vez. Si un valor choca con lo ya asignado, prueba el siguiente; si a una variable se le acaban los valores, retrocede y cambia la anterior. Si retrocede hasta el inicio, el problema no tiene solución.

Como el orden de los valores se baraja en cada partida, el niño ve combinaciones distintas, pero todas cumplen las reglas.

# Cómo se vería en backend/ia_models/escenarios.py (boceto)
def distractores(self, escenario, categoria, rng, n=3):
    dominio = [e for e in self.elementos_de(categoria)
               if e != escenario.objetivo[categoria]          # unaria
               and e not in escenario.confundibles]           # unaria
    rng.shuffle(dominio)
    def backtrack(elegidos):
        if len(elegidos) == n:
            return elegidos
        for e in dominio:
            if e not in elegidos and ambiente(e) not in {ambiente(x) for x in elegidos}:
                if (sol := backtrack(elegidos + [e])):
                    return sol
        return None                                           # retrocede
    return backtrack([])

El campo confundibles y el “ambiente” de cada elemento no existen hoy en escenarios.json; habría que agregarlos. Las listas de esta página son un ejemplo.

Parte 2

Algoritmo genético

Un algoritmo genético es una búsqueda inspirada en la selección natural. En lugar de mejorar una sola solución, mantiene una población de soluciones. Cada solución se escribe como un cromosoma, una cadena de genes, y una función de fitness dice qué tan buena es.

En K'iti Yachay, el agente actual (AgenteProgramado) siempre da las ayudas en el mismo orden: resaltar → pista → modelar, sin importar la categoría. ¿Será lo mejor para todas? El algoritmo genético puede buscar otra política.

Cromosoma
Una política de ayudas completa.12 genes: qué ayuda dar tras el 1.º, 2.º y 3.º error en cada una de las 4 categorías.
Gen
Una decisión.R = resaltar, P = pista, M = modelar (mostrar la respuesta).
Fitness
La nota de cada política.Puntaje esperado de un jugador simulado; más alto es mejor.

El ciclo de cada generación

  1. Evaluar. Se calcula el fitness de cada cromosoma de la población.
  2. Seleccionar. Por torneo: se toman 3 al azar y gana el de mejor fitness. Los buenos se reproducen más, pero los regulares también tienen oportunidad.
  3. Cruzar. Dos padres se cortan en un punto al azar; el hijo hereda la primera parte de uno y el resto del otro.
  4. Mutar. Cada gen del hijo tiene una probabilidad pequeña (6 %) de cambiar al azar. Sin esto, la población se estanca.
  5. Reemplazar. Los hijos forman la nueva generación. Los 2 mejores pasan sin cambios (elitismo), así nunca se pierde lo mejor encontrado.

El jugador simulado

El fitness necesita un modelo de cómo responde el niño. Este es inventado para la explicación: los números no vienen de datos reales. En el proyecto se usaría simulador.py, y lo ideal sería calibrarlo con la especialista.

  • Al primer intento acierta con probabilidad 0.35. Después de una ayuda, con la probabilidad de la tabla (repetir la misma ayuda rinde un 40 % menos).
  • Puntaje de la ronda: +10 si acierta sin que le muestren la respuesta, +3 si se la mostraron, −2 por cada error.
  • Tras cada error puede abandonar por frustración (22 % tras el 1.º error, 44 % tras el 2.º): −6. Modelar evita el abandono.

Con este modelo, el algoritmo suele descubrir que conviene cambiar la ayuda según la categoría: pista para animales (“vive aquí”), resaltar para construcciones y modelar enseguida para objetos, que son los más difíciles. El guion fijo no puede hacer eso.

Con 12 genes hay 3¹² = 531 441 políticas. Aquí todavía se pueden probar todas (es la línea punteada “óptimo” del gráfico) y por eso sabemos que el AG llega al óptimo. El AG vale la pena cuando el cromosoma crece (más categorías, más tipos de ayuda, el estado del niño) y probar todo deja de ser posible. Además, se ejecuta en tu PC: al servidor solo se sube la política ganadora, una tabla de 12 valores.
